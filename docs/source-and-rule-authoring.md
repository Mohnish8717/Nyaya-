# Source governance and capability authoring

The conversation is generated by the configured LLM. `prompts/legal_agent.md` defines the role and evidence limits; it contains no scripted answers. The capability catalog is a list of functions the assistant can perform, not a questionnaire. Only approved primary sources can support legal claims.

## Add a primary legal source

1. Use an official primary source or official court publication. Preserve the exact text and canonical source URL.
2. Add a unique source ID, authority, jurisdiction, source kind, tags, effective dates, and date checked to `data/legal_sources.json`.
3. Keep a new record at `review_status: "draft"` until a qualified reviewer checks its exact text, legal scope, amendments and limitations.
4. Preserve superseded text with its old effective interval. Do not silently rewrite history.
5. Legal claims must cite a retrieved record and a verbatim quote; the server checks the quote against the source text. This protects against invented citations but does not prove that the model's interpretation is correct.

Example record:

```json
{
  "id": "IN-KA-EXAMPLE-SECTION-1",
  "title": "Official title and provision",
  "authority": "Issuing authority",
  "jurisdiction": "IN-KA",
  "kind": "statute",
  "review_status": "draft",
  "effective_from": "2026-01-01",
  "effective_to": null,
  "checked_at": "2026-10-27",
  "url": "https://official.example.gov/source",
  "text": "Exact passage copied from the official source.",
  "tags": ["provision phrase", "common legal term"]
}
```

Reload source data using the protected admin route after `ADMIN_TOKEN` is set:

```bash
curl -X POST http://127.0.0.1:8000/api/admin/sources/reload \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

## Add court judgments

Use the supplied dataset importer for a selected partition. It records the dataset, attribution/license, court/date/citation fields and source URL when available. It preserves judgments as court records and marks treatment as unchecked. Do not infer a positive treatment relationship just because one judgment cites another.

The bulk datasets are too large for the shipped app workspace. For deployment, sync filtered partitions to object storage, normalize metadata, extract page-aware text, chunk by judgment structure, and index in a scalable hybrid search service. Keep the Supreme Court, each High Court, legislation and secondary Q&A in distinguishable namespaces. See [`DATA_SOURCES.md`](../data/DATA_SOURCES.md) and [`architecture.md`](architecture.md).

## Add a capability

Add a capability to `data/service_catalog.json` only if the implementation exists or the description clearly says it is an unimplemented future integration. Give it:

- a stable machine ID and user-facing label;
- a plain-language description of the work the assistant may perform;
- a side-effect class, including whether user authorization is required;
- source and data requirements plus explicit non-goals.

Do not add a fixed legal reply or fixed follow-up question as a capability. Let the model generate a response from the current facts, jurisdiction and retrieved evidence. Keep external calls behind explicit user action, a server authorization check, and a separate sharing-consent step.

## Review and deployment

Before enabling a source or capability publicly, have a qualified reviewer assess positive, negative, ambiguous, wrong-jurisdiction, outdated-source, contradictory-fact and malicious-document examples. Evaluate all output languages separately, including names/dates/negations from Prisma and correct legal terminology in Timbre speech. A model-generated confidence score or an exact quote check is not a substitute for that review.
